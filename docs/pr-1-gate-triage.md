# PR #1 full-gate triage

This note records the baseline for PR #1, `Add AW website migration process and checklist`, before any fixes in this continuation. The tested head was `1b775f18f7758cb42103db6313bda1a522468ec3`; the PR remains open and must not be merged until its checks have completed and blockers are understood.

## Reproduce the baseline

The baseline ran on Linux with Node `v22.23.4` and npm `10.9.9`. The kit's `test:gates` cases require the template's locked dependencies because the HEIF fixture is generated by the same `sharp` dependency used by the template pipeline. Install them first, then run the full suite:

```sh
cd template && npm ci --no-audit --no-fund
cd .. && npm run test:gates
```

The first attempt before installing `template/node_modules` stopped while constructing the HEIF fixture (`Cannot find module 'sharp'`) and did not reach the case summary. That was an environment/setup failure, not one of the seven test failures. After the lockfile install completed, the unmodified PR head exited 1 with **7 of 239 cases failing**. The complete case-by-case baseline output is preserved in [`evidence/pr-1-test-gates-before-fixes.log`](evidence/pr-1-test-gates-before-fixes.log).

## Failure classification

| Failing case | Baseline evidence | Classification and correction |
| --- | --- | --- |
| `says nothing about orphans on a site where everything is linked` | The fixture server did not start on port `8340`. | Environment-specific port collision exposed a brittle test harness. `ss -ltnp` showed the sandbox's `runtime-upgrade` service already listening on `8340`. The harness now asks the OS for an ephemeral loopback port and retries bounded startup attempts. |
| `a clean site passes AA in both schemes` | The fixture server did not start on port `8350`. | Same root cause; `ss -ltnp` showed the sandbox's `sandbox-runtime` service already listening on `8350`. No accessibility assertion ran in that case. The same ephemeral-port fix covers it. |
| `a tree of ordinary source files passes` | `check:binary` exited 1 on text-only fixture files. | Reproducible detector bug under this environment's forced Git color: `GIT_CONFIG_COUNT=1`, `GIT_CONFIG_KEY_0=color.ui`, `GIT_CONFIG_VALUE_0=always`. `git grep -I -l ''` emitted ANSI-decorated filenames while `git ls-files` returned plain paths, so the textual-path set comparison falsely classified files as binary. `binary-files.mjs` now passes `--no-color`. |
| `an empty file is not mistaken for a binary one` | `check:binary` exited 1 although the only non-empty source was ordinary text. | Same color-output parsing bug; the empty-file exclusion itself was not the cause. The shared detector fix addresses it. |
| `a site with everything reports no drift` | Exit status was 0, but the report did not say `nothing behind`. | Downstream symptom of the same false binary finding in the shared detector; the intentionally clean fixture appeared drifted only because Git color corrupted path comparison. |
| `a run that does force the scheme is not reported` | Exit status was 0, but the clean-state phrase was absent. | Same shared-detector false positive; no separate D9 regression was established. |
| `the template itself is not a drifted site` | Exit status was 0, but the clean-state phrase was absent. | Same shared-detector false positive; the template's special-case behavior was not the failure. |

The two startup failures were caused by reserved ports in this sandbox, not by a broken fixture-site handler. The five text/drift failures share one code defect: parsing `git grep` output without disabling inherited color. The NUL-bearing-file refusal case still passed on the baseline, so the detector did find the intended binary fixture; the defect was the clean-file false positive.
